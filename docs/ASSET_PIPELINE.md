# Sprite and asset pipeline

Copied from the claude.ai doc "Two Wards: sprite and asset pipeline" (2026-10-22, https://claude.ai/artifact/JKvijvLoqSBC3ei9scDWnD) so it lives in the repo.

> **Read this first: some numbers here are out of date.** The doc was written before the switch to 640×360 (PR #6) and before the pipeline was built (PR #4). Where it differs from the repo, the repo wins:
>
> - Base resolution is 640×360, not 320×180. Units are 64×64 per frame, tiles 32×32, card art 128×96, icons 32×32.
> - The manifest is `game/assets/manifest.json`, not `tools/asset_manifest.yaml`.
> - The pixel font is m5x7 (PR #8). The six "gaps" at the end were all decided (PR #4 and #6) and are in `docs/PLAN.md`.
> - "Order of work" is superseded by the art track A1–A4 in `docs/PLAN.md`: real art starts at A1 with a target frame, not at M6.
> - Current style rules are in `docs/STYLE_GUIDE.md`.

## Short answer

Keep the tool choice from `docs/PLAN.md`: **PixelLab generates, Aseprite cleans up, a validation script enforces, a Godot import script wires it in.** Commit only the exported PNGs plus the `.aseprite` sources; Godot resources (`SpriteFrames`, `TileSet`) are generated from the PNGs by a script, never hand-built in the editor.

## Tools

| Tool | Use it for | Notes |
|---|---|---|
| PixelLab (paid) | Units, 4-direction rotations, walk/attack animations, tilesets | Generates at native size, accepts a style reference image, and has an API so Claude can batch-generate from the manifest. Always pass an anchor as the style reference. |
| Aseprite | Palette snap, outline fixes, frame timing, tags | Load Endesga 32 as the palette, then Sprite > Color Mode > Indexed to snap stray colors. One `.aseprite` file per unit with one tag per animation+direction. |
| Aseprite CLI | Export | `aseprite -b hero.aseprite --split-tags --sheet-type horizontal --sheet game/assets/units/hero/unit_hero_{tag}.png` exports one strip per tag in one command. Only needed on your machine, not in CI. |
| Claude | Manifest, prompt templates, validator, import script, placeholder art | Placeholders generated by code already pass validation, so the pipeline is tested long before real art exists. |
| Backup only: Retro Diffusion (Aseprite plugin) | Fallback if PixelLab drifts | Avoid general image models (Midjourney, DALL-E, SD without pixel LoRA): they produce fake pixel art with sub-pixel noise that costs more cleanup than it saves. |

## Folder layout

    assets-src/
      palette/endesga-32.gpl        # Aseprite/GIMP palette (tools/endesga32.hex for the validator)
      anchors/                      # the hand-polished references
      units/<name>/...              # .aseprite sources, raw PixelLab outputs
      tiles/, cards/
    game/
      assets/
        manifest.json               # every asset: id, type, frames, fps, loop, status
        units/<name>/unit_<name>_<anim>_<dir>.png   # horizontal strips
        tiles/<set>/tile_<set>_<nn>.png
        cards/card_art_<id>.png
        icons/icon_<name>.png
        towers/tower_<id>.png       # 48×72, base at the tower's position
        props/prop_<name>.png       # size from the manifest entry
        fonts/
      resources/generated/          # SpriteFrames + TileSet .tres written by the import script
      tools/build_assets.gd         # import script, runs headless (must live inside res://)
    tools/
      validate_assets.py            # the validator (Python + Pillow)
      make_placeholders.py          # code-drawn placeholders for "placeholder" entries

The import script has to live under `game/` because Godot can only run scripts inside the project; the language-agnostic validator stays in the top-level `tools/`.

## Godot settings

- Display: viewport 640×360, stretch mode `viewport`, scale mode `integer`.
- Rendering: default canvas texture filter `Nearest`; snap 2D transforms and vertices to pixel.
- PNG import: lossless, no mipmaps.
- Pixel font: import with antialiasing off, hinting none, subpixel positioning off; use it only at its native size or integer multiples.

## Units: strips to AnimatedSprite2D

- One PNG per unit/animation/direction, as a **horizontal strip of 64×64 frames**. Frame count = width / 64.
- Directions: draw `down`, `up`, `side` (facing right) and get left with `flip_h`. Three drawn directions instead of four or eight saves a quarter to half of all generation and cleanup.
- `build_assets.gd` reads the manifest, slices each strip into `AtlasTexture` regions and writes one `SpriteFrames` per unit with animations named `<anim>_<dir>` (`walk_down`, `attack_side`). FPS (8–12) and loop come from the manifest; idle and walk loop, attack does not.
- `UnitData` holds a reference to its `SpriteFrames`, so a new unit stays data-only: art + manifest entry + `.tres`, no code.
- Run it with `./tools/build_assets.sh` (`.ps1` on Windows). Commit the generated `.tres`; CI reruns it and fails on `git diff`, so resources never drift from the PNGs.

## Tiles

PixelLab tilesets come out as one sheet. Keep per-tile naming (`tile_base_00.png` ...) so the validator stays simple, and have the import script pack them into one `TileSetAtlasSource` and write the `TileSet` resource. For the PoC, skip terrain autotiling; hand-place tiles.

## Cards

Hand-made rarity frame + `card_art_<id>.png` in a `TextureRect` + cost, name and text as `Label`s in the pixel font. The card scene builds itself from `CardData`, so balance changes never touch art.

## Atlases

No global texture atlas for the PoC. The per-animation strips already are small atlases, Godot 4 batches 2D draws on its own, and the asset count is tiny. Revisit only if profiling says so.

## Validation step

`tools/validate_assets.py` runs as a pre-commit hook and in the CI lint job. For every PNG under `game/assets/`:

1. **Name** matches one of the patterns (`unit_`, `tile_`, `card_art_`, `icon_`, ...).
2. **Size** by type (see `docs/PLAN.md`).
3. **Palette**: every pixel with alpha > 0 is one of the 32 Endesga colors.
4. **Transparency**: alpha is only 0 or 255 (no soft edges from AI output).
5. **Manifest**: every PNG has a manifest entry and every finished entry has its PNG; frame count matches.

It prints all failures with file and pixel coordinates and exits non-zero.

## Running it on Windows

Everything runs natively on Windows, no WSL needed:

- **Validator**: plain Python + Pillow, so `py tools\validate_assets.py` works the same as on Linux (`py -m pip install -r tools\requirements.txt`).
- **Pre-commit hook**: `py -m pip install pre-commit`, then `pre-commit install`. It runs the Python validator directly.
- **Aseprite export**: the same CLI flags work with `"C:\Program Files\Aseprite\Aseprite.exe" -b ...` (Steam installs live under `steamapps\common\Aseprite`).
- **Import script**: `.\tools\build_assets.ps1`.
- **Paths**: Godot resources use `res://` paths, so generated `.tres` files are identical on Windows and in CI.

## Original order of work (superseded by the art track)

1. M1–M5: gray boxes, plus code-generated placeholders that already pass the validator.
2. Anchors by hand (hero, goblin runner, base tileset, one card art); fix the style guide where reality disagrees.
3. Then batch: manifest entry, PixelLab with anchor reference, Aseprite pass, export, validator, import script, mark done.
4. A side-by-side review screen in game (all units on the base tileset) as the consistency check.
